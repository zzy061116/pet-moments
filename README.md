# 宠物朋友圈 🐾

> 给你家猫狗开一个朋友圈号。它负责活着，AI 负责把它今天干的破事写成动态，
> 隔壁的猫、楼下的狗、前主人家那只仓鼠，会来评论区抬杠。

不用注册、不用训练模型、不用 GPU。**没有 API Key 也能完整玩一遍**（内置离线文案引擎）。

---

## 30 秒跑起来

需要先装好 [Python 3.10+](https://www.python.org/downloads/)（Windows 安装时记得勾选 `Add Python to PATH`）。

```bash
# 1. 装依赖（只装 4 个包）
pip install -r requirements.txt

# 2. 启动
uvicorn app.main:app --reload --port 8010

# 3. 打开浏览器
# http://127.0.0.1:8010
```

第一次打开会看到创建页。**不想填表？** 直接点最下面那行「先看看示例：一只叫豆花的猫」，
会载入一只英短 24 天的完整朋友圈，包含人设、文案、点赞和评论区吵架。

> 如果你的 `python` 命令没反应（Windows 商店占位程序），把上面命令里的 `pip` 和 `uvicorn`
> 换成完整路径的形式，或者用 `python -m uvicorn app.main:app --reload --port 8010`。

## 想让它真的聪明？填个 Key（可选）

```bash
# Windows
copy .env.example .env
# macOS / Linux
cp .env.example .env
```

然后编辑 **`.env`**（不是 `.env.example`，那个文件会提交到仓库，填进去等于公开 key），
填一个 OpenAI 兼容接口的 key：

```ini
LLM_API_KEY=sk-你的key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```

不想手动改格式就运行 `python scripts/set_key.py`，选平台、粘 key，它会写好文件并立刻验证。

**不想充钱**的话把两行换成智谱（`glm-4-flash` 这个模型免费，实测单条生成 5~8 秒）：

```ini
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
LLM_MODEL=glm-4-flash
```

填完先验证一次，别急着开页面（这一步能省掉 90% 的排查时间）：

```bash
python scripts/check_llm.py
```

它会把当前读到的 base_url / model / key（打码）打出来，然后真的请求一次，成功就打印
模型生成的人设卡和一条朋友圈；失败会直接告诉你原因，比如：

| 报错 | 通常是 |
|---|---|
| `HTTP 401` | key 粘错了，或者多粘了引号/空格 |
| `HTTP 404` | base_url 少了 `/v1`，或模型名写错 |
| `HTTP 402` | 余额不足，DeepSeek 新号要先充值 |
| `ConnectError` / `Timeout` | 网络或系统代理问题 |

验证通过后重启服务，宠物名下方的状态标签会从「演示模式」变成「AI 在线」。

DeepSeek / 通义千问 / Kimi / 智谱 / 本地 Ollama 都行，`.env` 里有现成写法。
**没填也不影响使用**：会自动退回离线引擎，用「事件类型 + 人设卡」拼出文案，不会报错。
如果填了 key 但文案还是像模板，看一眼 `http://127.0.0.1:8010/api/health` 里的 `llm_error`。

## 它是怎么"像同一只猫"的

大多数 AI 宠物玩具做到第三天就崩了：每次生成都像换了一只动物。这里靠三件事兜住。

**1. 人设卡先落库，不是每次现编**

创建宠物时先生成一张结构化卡片并写进 SQLite：

```json
{
  "tags": ["嘴硬心软", "贪吃", "半夜跑酷"],
  "nickname": "本喵",
  "catchphrase": "这事跟我没关系",
  "obsession": "凌晨三点在走廊冲刺",
  "fear": "吸尘器",
  "tone": "短句，爱用括号补充内心戏，不用感叹号"
}
```

之后每一条动态都把这张卡塞进 prompt。人设是**数据**，不是一句模糊的「你是一只可爱的猫」。

**2. 只写今天这一件事**

prompt 里明确禁止编造长期剧情、禁止写日期、禁止"作为一个 AI"。上限 90 字。
模型被限制在一个小盒子里，反而更稳。

**3. 评论区的人是写死的**

三个好友的性格固定在后端（`app/prompts.py`）：胖虎毒舌、豆豆捧场、球球阴阳怪气。
模型只负责写台词，**名字不让它改**——它要是自己发明第四只猫，后端会直接覆盖掉。

而且评论的语气会随连续发布天数变化：第 1 天是「你是？」，第 7 天变成「怎么今天才发，等你半天」。

## 养成是怎么算的

| 机制 | 规则 |
| --- | --- |
| 经验 | 每条动态 +12，连续天数额外加成（最多 +20） |
| 称号 | 沙发土豆 → 拆家学徒 → 干饭专家 → 撒娇大师 → 一家之主 |
| 连续天数 | 隔天发布 +1，断更超过一天归 1，同一天重复发不涨 |
| 社交 | 连续 4 天以上，三个好友会全部点赞，评论开始催更 |

等级、经验、连续天数都是纯本地规则，不花一次模型调用——**养成感不该依赖 API 稳定性**。

## 目录结构

```
pet-moments/
├── app/
│   ├── main.py       # 接口：建宠物 / 发动态 / 传图 / 载入示例
│   ├── service.py    # 编排：先问大模型，失败或没 key 就切离线
│   ├── prompts.py    # 人设卡 prompt + 文案 prompt + 三个好友的人设
│   ├── offline.py    # 离线引擎：8 类事件 × 文案模板 × 评论池
│   ├── db.py         # SQLite，两张表
│   ├── llm.py        # OpenAI 兼容调用，任何异常都返回 None
│   └── seed.py       # 豆花的 24 条示例数据
├── web/              # 单页前端，原生 JS，没有构建步骤
├── scripts/
│   └── smoke_test.py # 不打开浏览器也能自检整条链路
└── data/             # 运行时生成：pet.db + uploads/
```

只有两张表：`pet`（一只）和 `post`（动态）。想加多宠物，把 `pet.id CHECK (id = 1)` 去掉就行。

## 常见问题

**端口被占用？** 换成 `--port 8011`，浏览器地址跟着改。

**照片传不上去？** 只支持 jpg / png / webp / gif，单张不超过 8MB。

**"存图"按钮没反应？** 那个按钮依赖 CDN 上的 html2canvas，断网时用不了。
改成手动截图：长按那条动态 → 保存图片，效果一样。

**想让它写狗？** 创建时把品种填成「柯基」，人设卡会自动偏过去；离线引擎的评论池里也有狗的台词。

**数据存在哪？** `data/pet.db`，删掉这个文件就等于恢复出厂。上传的图片在 `data/uploads/`。

## 它是怎么被做出来的

这个项目的全部代码由 AI 助手在 CodeBuddy 里生成，人只负责定方向：
「做一个普通人看完就想给自己猫也弄一个的东西」。

三个决定性的取舍：

1. **先做能截图的成品，再谈技术。** 朋友圈卡片 + 评论区是这个作品的传播单元，
   所以前端一张卡片的排版比后端架构重要。
2. **离线可用是硬要求。** 评审和路人不会为了看你的作业去申请 API Key，
   自带模板引擎让它在断网、无 key、模型 500 的情况下都能完整演示。
3. **养成规则不交给模型。** 等级、经验、连续天数全是确定性代码，
   AI 只负责"说话"这一件事。
